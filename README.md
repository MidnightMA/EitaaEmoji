# سیستم اطلاع‌رسانی به کاربران ایتا (Notification System)

## ⚠️ وضعیت فعلی: آماده ولی دیپلوی‌نشده

بازی رازک یک **سایت کاملاً استاتیک** است (`index.html` + `app.js` +
`style.css` + `data.json`، روی GitHub Pages؛ بدون هیچ سرور Node.js/PHP و
بدون هیچ دیتابیس واقعی — «ذخیره‌سازی ابری» فعلی هم فقط یک تماس مستقیم از
مرورگر به KVDB.io است).

فرستادن پیام از طرف برنامه به کاربر، نیاز به یک **توکن مخفی** دارد
(`EITAA_APP_TOKEN`). این توکن **مطلقاً نباید** در کدی که به مرورگر کاربر
فرستاده می‌شود (یعنی `app.js` یا هر فایل دیگری که با `<script>` لود
می‌شود) قرار بگیرد — هرکسی با باز کردن Network tab یا View Source
می‌تواند آن را بردارد و به‌جای شما پیام بفرستد.

به همین دلیل، فایل `send-notification.js` (کنار همین README) عمداً به
هیچ‌جای بازی وصل نشده. این فایل یک **template آماده‌ی استفاده** است؛ تا
وقتی یک بک‌اند واقعی (هر سروری که بتواند متغیر محیطی مخفی نگه دارد)
اضافه نکنی، این قابلیت غیرفعال می‌ماند.

## این تابع دقیقاً چه‌کاری انجام می‌دهد

`sendMessageToUser(userId, message)` طبق مستندات رسمی ایتا
(https://developer.eitaa.com/docs/Develop/SendMassage) به این آدرس
درخواست می‌زند:

```
POST https://eitaayar.ir/api/app/sendMessage
{ "token": "...", "chat_id": <آیدی عددی کاربر در ایتا>, "text": "..." }
```

## مجوز لازم (مهم‌ترین نکته)

طبق همان مستندات، پیام فقط به کاربری قابل ارسال است که **از قبل به
برنامه‌ات اجازه‌ی ارسال داده باشد** — این اجازه فقط با یکی از این دو راه
به‌دست می‌آید:
1. کاربر روی دکمه‌ی «شروع» (Start) برنامه/بات کلیک کرده باشد، یا
2. کاربر برنامه را از طریق یک لینک مستقیم داخل یک پیام باز کرده باشد.

**صرفاً باز کردن مینی‌اپ رازک به‌تنهایی کافی نیست.** یعنی این را نمی‌شود
فرض کرد که هرکسی که تا حالا بازی کرده، پیام هم می‌تواند دریافت کند؛ باید
جدا بررسی/امتحان شود (تلاش ارسال کن، اگر `ok:false` برگشت، یعنی یا اجازه
نداده یا آیدی اشتباه است).

## شناسه‌ی کاربر از کجا می‌آید

نیازی به سیستم شناسایی جدید نیست — رازک از قبل همین الان هم آیدی ایتای هر
کاربر را دارد: در `app.js`، متغیر `GameState.user.id` مستقیماً از
`window.Eitaa.WebApp.initDataUnsafe.user.id` (SDK رسمی ایتا) پر می‌شود.
همان مقدار، همان `chat_id` ای است که این تابع نیاز دارد.

## دیپلوی کردن (وقتی آماده بودی)

۱. یکی از این‌ها را انتخاب کن (همه رایگان برای این حجم ترافیک هستند):
   Vercel Serverless Functions، Netlify Functions، یا Cloudflare
   Workers.
2. فایل `send-notification.js` را داخل ساختار همان پلتفرم بگذار (مثلاً
   برای Vercel: `api/notify.js`، با یک export پیش‌فرض که `req.body` را
   می‌خواند — نمونه‌ی کامل در انتهای خودِ `send-notification.js` هست).
3. در تنظیمات همان پلتفرم (نه در کد!)، یک Environment Variable به اسم
   `EITAA_APP_TOKEN` بساز و توکن برنامه‌ات (از پنل ایتایار) را آنجا
   بگذار.
4. آن endpoint را حتماً پشت یک بررسی مجوز/ادمین بگذار — بدون آن، هرکسی
   می‌تواند از آن برای اسپم کردن کاربرهای شما استفاده کند. این پروژه فعلاً
   هیچ سیستم ادمینی ندارد، پس این بخش را هم باید خودت طراحی کنی (مثلاً
   یک کلید مخفی ساده در هدر درخواست، یا احراز هویت واقعی).

## محدودیت‌هایی که ایتا اعمال می‌کند

- توکن فقط از پنل ایتایار (eitaayar.ir) قابل دریافت است.
- فرمت متن از یک Markdown ساده پشتیبانی می‌کند: `**پررنگ**`، `__کج__`،
  `` `کد` ``، `[متن](لینک)`.
- هر پاسخی غیر از `{"ok": true, "result": "success"}` یعنی ارسال ناموفق
  بوده (دلیل دقیقش در پاسخ همیشه شفاف نیست).
- محدودیت نرخ ارسال (rate limit) دقیق در مستندات عمومی ذکر نشده؛ برای
  ارسال به تعداد زیاد کاربر، بین درخواست‌ها فاصله بگذار و پاسخ‌های ناموفق
  را دوباره‌امتحان نکن به‌صورت فوری/پشت‌سرهم.
